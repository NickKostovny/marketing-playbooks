# Recipe: SEO gap check before writing an explainer

Tooling: an SEO MCP with keyword metrics, live SERP fetch, related-keyword research, and a shared project context. I use OpenSEO, which sits on DataForSEO data. Any equivalent works; the steps are the point.

## 1. Read the project context first

Read the shared context and the research log before buying data. It tells you the site's goal, the baseline, what was already bought, and when it is safe to re-buy. Skipping this step is how you pay for the same sweep twice.

## 2. Confirm the gap on your own site

Grep the site repo for the topic term. Check the sitemap and the blog folder. Note every page that mentions it and whether any ranks. If a page already ranks, you are refreshing, not writing.

## 3. Size the demand with a candidate list

Write 40 to 140 candidate keywords by hand: the head term, the acronym expansion, "what is," "meaning," "vs" pairs, protocol siblings, vendor product names, and the domain-modified versions you assume people search. Pull volume, difficulty, and intent for all of them in one call, with monthly trend data off.

Two rules:
- A keyword that comes back missing has zero measured volume. Diff your input list against the output.
- Domain-modified terms often come back empty. That is a finding, not a failure. It tells you to write the generic term for your domain, not the domain term.

## 4. Look at who ranks

Fetch live SERPs for the head term and two or three modified queries, ten results each. Record the domains, the content type (vendor page, standards body, Wikipedia, forum, video), and whether an AI Overview sits on top. Set the realistic ceiling from this, not from the difficulty score.

## 5. Get the related set

Run related-keyword research on the head term once. Flatten the result and read the top 70 by volume plus everything with a question or comparison word. This is where the variants come from that one page can hold together.

## 6. Decide the format

- Generic informational cluster, low difficulty, no domain-native page in the top ten: write the definitional explainer, domain-first, with a heading for each variant and an FAQ for the long tail.
- Head term owned by regulators or Wikipedia: target positions 6 to 10 and let the variants carry the top-ten count.
- Modifiers like pdf, notes, jobs, or a chemistry homonym with big volume: skip. It hits a keyword target and produces nobody who will buy.

## 7. Record it

Write the findings back to the shared project context: the keyword table, the SERP cast, the decision, the credits spent, and a do-not-re-buy-before date. When the piece ships, add its URL as a key page with the target terms and the date, so the ranking check three months later has a baseline.
